Methodology

Unassigned open work

Open issues with no assignee. Nobody is individually accountable for the work.

Overdue unresolved work

Open issues whose due date has passed. Counted in calendar days in the configured display timezone; an issue due today is not overdue.

Stale open work

Open issues with no recorded Jira activity beyond the stale threshold. An inactivity signal, not proof that work has stopped.

High-priority stale work

Issues at a configured high priority with no recorded activity beyond the tighter high-priority threshold.

Excessive current-status age

Open issues that have remained in their current working status beyond the threshold, measured from the latest status transition in the changelog.

How ages are counted

  • All ages are counted in whole calendar days in the display timezone shown under Scan metadata — not business days, and not an SLA calendar.
  • Thresholds are exclusive: at a 30-day stale threshold, an issue last updated exactly 30 days ago is not reported; 31 days is.
  • An issue due today is not overdue.
  • Jira's 'updated' field moves for automation runs and administrative edits that represent no human progress, and does not move when someone works on an issue without touching it. Treat the stale checks as inactivity signals, not proof.
  • Current-status age is measured from the most recent status transition in the issue's changelog. Where an issue has never transitioned, it is measured from the creation date instead.
  • Issues sitting in a backlog status such as 'To Do' will be reported for status age once they pass the threshold. If a long-lived backlog is normal here, add that status to the excluded list so the report shows work that is genuinely stuck in flight rather than work that has not started.

Limitations

  • Findings cover only the issues the authenticated account can browse. Issue-level security or project permissions may hide work from this scan entirely.
  • JiraLens is read-only. It made no change to any issue, field, workflow or configuration while producing this report.
  • Issue descriptions, comments, attachments and worklogs are never retrieved, so none of that content appears here and none of it was held in memory.
  • There is no health score. A single number would depend on arbitrary weights and would read as more precise than the underlying data supports.
